# Task: Show the host on tiles when a service name isn't unique

Since v0.6.1 the Tiled tile face has no host line. Entries with the same name
on different hosts (technitium on em-dns01 and em-dns02, traefik and
komodo-periphery on several hosts) therefore look identical. Show the host
where it tells entries apart, controlled by a new setting. This is the fifth
chunk of v0.9.0.

## What to do

1. **Setting `tile_show_host`.** Allowed values are `duplicates` (the
   default), `always` and `never`.
   - Read it in `settings_loader`, with the env override `TILE_SHOW_HOST`
     following the existing naming pattern.
   - Lower-case and trim the value. An unknown value logs a warning and falls
     back to `duplicates`, the way other invalid settings are handled.
   - Add it to `settings.example.yml` with a comment.
   - It is **not editable at runtime**, like every other settings.yml value.
     "Settings page" here means it shows in Settings → Info with the rest of
     `current_config`. Confirm it appears there, and add it explicitly if Info
     uses an allow-list.
   - `GET /api/v1/config` returns it (not a secret). Update the response
     schema, OpenAPI and its test.

2. **Duplicate detection.** Add `view_helpers.duplicate_name_ids(entries)`,
   which returns the set of entry ids whose name is shared by another
   **active** entry on a **different** host.
   - Compare names case-insensitively, with surrounding whitespace trimmed.
   - Soft-deleted entries (`deleted_at` set) are ignored entirely.
   - Entries with no host (manual) are never marked, and a NULL host does not
     count as "a different host" for the others either.
   - Compute it over **all active entries**, not just the filtered or visible
     ones, so a filter doesn't make a duplicate look unique.
   - Then add `view_helpers.host_label_ids(entries, mode)`, which returns the
     ids that should show a host:
     - `never` gives the empty set;
     - `always` gives every entry with a host;
     - `duplicates` gives the result of `duplicate_name_ids`.
   - Pass the resulting set to the templates. Don't compute it in Jinja.

3. **Tiled view.** On the tile face, directly under the name, show the host
   in small, muted text for ids in the set. Truncate it with ellipsis, and put
   the full host in `title`. Tiles not in the set look exactly as they do now:
   don't add an empty line or change the tile height for them. Match the
   existing tile CSS (`static/css/dashboard.css`). Check the narrow (390px)
   layout doesn't break.

4. **Compact view.** Replace the `len(unique_hosts) > 1` rule with the same
   set, and show the host after the name the way the existing `.host-name`
   element does, per entry. With the default `duplicates`, operators who saw
   hosts on every compact tile will now see them only on duplicates. Note
   that under CHANGELOG → Changed, and point to `tile_show_host: always` to
   get the old look back. The old rule was "more than one host"; `always`
   shows the host on every entry that has one, which is close enough. Say so
   in the decisions entry.

5. **Dashboard table.** It already has a Host column, so make no change, and
   confirm it.

6. **Tests:**
   - `duplicate_name_ids`:
     - the same name on different hosts is marked, for both entries;
     - a case or whitespace difference still counts as a duplicate;
     - a deleted twin doesn't count;
     - a unique name is not marked;
     - a manual entry with no host is never marked, and a no-host twin
       doesn't mark the hosted one;
     - the function is computed over all active entries even when the view
       is filtered (a route-level test).
   - `host_label_ids` for all three modes.
   - Settings: default, env override, invalid value falls back with a
     warning.
   - The tiled and compact HTML shows the host for the duplicate pair and not
     for a unique entry, in each mode.
   - `/api/v1/config` includes the value.
