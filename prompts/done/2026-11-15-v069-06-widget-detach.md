# Task: Detach widgets on hard delete (PRD §12.6)

When a service is hard-deleted (purge or Delete permanently), keep its widget config as a "detached" widget that can be re-attached, instead of deleting it.

## What to do

1. In `hard_delete_entry`, stop deleting the `Widget` and its `WidgetValue` rows. Delete the entry only, so the widget becomes unreferenced.
2. Define "detached" in one place (for example a `Widget.detached()` query): no `ServiceEntry` row of any kind (active or soft-deleted) references it.
3. The widget refresh job skips detached widgets. Retention pruning of `widget_value` is unchanged.
4. Add a "Detached widgets" section to Settings → Deleted: widget name/type, URL, last value time, and two actions:
   - **Attach to service:** a picker of active entries with `widget_id IS NULL`; sets that entry's `widget_id`.
   - **Delete:** removes the widget and its values.
   Both are admin-only POSTs with a CSRF token.
5. Check that the edit page's widget handling doesn't orphan widgets in a new way. If changing an entry's widget type already creates a new `Widget` row, the old one now becomes detached rather than leaking silently. Report what you find, and change existing edit-page behavior only if it's clearly a bug.
6. Tests: a hard delete leaves the widget detached; the refresh job skips it; attach makes it active again; delete removes it with its values.
