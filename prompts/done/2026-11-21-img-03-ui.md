## Notes from `img-02`, verified by the orchestrating session

- **Effective state:** use `image_update.effective_state(entry)` for the badge, the
  `?updates=1` filter and the details line, never the raw `image_update_state`. It
  returns `off` while the check is disabled. The stored column would otherwise show stale
  updates.
- **What `image_update.py` and `jobs.py` give the UI:**
  - `effective_enabled()` → `(enabled, origin)`: `origin` tells you when the env var
    locks the switch.
  - `default_scope()`, `last_run()` and `jobs.image_update_next_run()`.
  - `request_check(app, entry=None)`: raises `CheckRequestError` with `.status` (409 when
    off, 429 when throttled) and `.retry_after`.
  - `validate_tag_pattern()`.
- **Saving the switch from the UI** must call
  `image_update.on_settings_changed(app, was_enabled)` afterwards. The API route already
  does.
- **Per-entry fields:** `image_update_state`, `_latest`, `_kind`, `_since`, `_provider`,
  plus `image_update_detail` (JSON: `reason`, `model`, `rebuilt`, the muted "rebuilt
  upstream" note), and `image_info` (has `version` and `source`). The remote facts live
  on `image_reference` (ORM attribute `registry_name`, not `registry`), joined by
  `ref = image_ref`. The management API entry serializer's `image_update` block shows
  how to read them all.
- **No live preview for an unsaved pattern.** Candidates are stored per pattern *in use*,
  so a newly saved pattern shows `unknown` "applies at the next check" until a run. Show
  the preview only for the saved pattern, from its stored candidates. For an edited,
  unsaved pattern, say "applies at the next check". Don't add a registry call.
- **N+1 guard:** the serializers cache the enabled flag per request in `g`, because a
  missing settings row isn't cached by the session. Views listing many entries must do
  the same (one `effective_enabled()` per request). `test_list_query_count_is_flat` is
  the existing guard; add a similar one for the dashboard views if practical.
- **PRD:** the image update section is §24 (after §23 Open Questions), not a renumbered
  section. Add the UI parts there.

## What to do

1. **Badge** on Dashboard rows, Tiled tiles and Compact cards, only when the state is
   `update`.
   - A small Tabler icon next to the name. Match how the other icons are loaded in
     `static/icons/` or the existing icon approach; don't add a CDN.
   - Tooltip: "Newer image: 1.5.0 (minor)" for the tag model, or "Image updated upstream
     (latest, pushed 2 d ago)" for the digest model.
   - It needs an accessible label. Hide it entirely when the global switch is off.
2. **Filter:** an "Updates available (N)" toggle (`?updates=1`) beside the existing
   status/source filters on all three views.
   - Handle it in `view_helpers`, like the status filter, as a plain predicate on the
     stored state column.
   - It must combine with the other filters and survive the view switcher links.
   - Hide it when the switch is off.
3. **Entry details** (`partials/entry_facts.html`, under the Docker image line). The
   line per state:

   | State | Line |
   |---|---|
   | `update`, tag model | "Update: **1.5.0** available (minor) · checked 2 h ago" |
   | `update`, digest model | "newer `latest` pushed 2 d ago (running <version label if known>) · checked …" |
   | `current` | "Image up to date · checked …" |
   | `unknown` | the stored reason, e.g. "needs notifier 0.5.0 or later for `latest` tags" |
   | `error` | the short stored error, muted |
   | `pinned` | "Pinned by digest" |
   | `off` | nothing |

   - The muted "rebuilt upstream" note goes wherever `img-02` stores it.
   - Add a release-notes link when the stored `image_info.source` is a GitHub URL
     (`<source>/releases`), with `target="_blank" rel="noopener noreferrer"`.
   - Add an admin-only **Check now** link per entry. It POSTs to the existing per-entry
     run path, with CSRF as the other UI forms use it, and toasts the throttle message
     when it is throttled ("checked 3 min ago, try again later").
   - Relative times: reuse whatever helper the views already use.
   - All three views share the partial, so check each one.
4. **Entry edit** (`/edit/<id>`, Docker entries only): an "Image updates" block.
   - **Policy:** Auto / Newer tags / Digest / Off.
   - **Scope:** Default / Any / Same major / Same minor.
   - **Tag pattern:** a regex, validated server-side with `img-02`'s validator. An
     invalid value flashes an error and changes nothing.
   - A live "matches: …" preview computed from the stored candidates. Use a small
     endpoint or inline data, with **no registry call**. Skip the preview if it would
     need back-end work beyond a read-only helper; flag that instead.
   - Saving recomputes the entry's state locally, with no network, using `img-02`'s
     recompute function.
5. **Settings → Sources → Image updates** (slug `image-updates`). Register it in
   `settings_sections.py` and build it with the `_macros.html` components.
   - An **Enabled** switch (default off) with one line saying what it sends where (the
     image names go to their public registries), plus **Default scope**.
     - No interval field. The text says "Checks once a day".
     - If `STD_IMAGE_UPDATE_ENABLED` is set, show the switch as locked by env, matching
       how other env-overridden settings render.
   - A **status card**:
     - last run (time, references checked, updates found, errors);
     - next run;
     - a **Check now** button (throttled once per hour, with the message when
       throttled).
   - A **problems list:** references in `error`, with the error and the entries that use
     them.
   - On the Docker section, a one-line hint pointing to the new section while it's off.
6. **Tests:**
   - Template/route tests:
     - the badge shows only on `update` and is hidden when the switch is off;
     - the filter works and combines with the other filters;
     - each details state renders;
     - the edit block saves and validates, including pattern rejection;
     - the Settings section renders, saves and shows the env lock;
     - Check now is throttled, admin-only, and protected by CSRF.
   - No network.
   - Run `uvx ruff@0.15.17 check .` and the FULL suite
     (`uvx --with-requirements requirements-dev.txt pytest -q`); both must pass.
