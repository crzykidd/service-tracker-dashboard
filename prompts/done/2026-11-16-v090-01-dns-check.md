# Task: DNS service check (new check type `dns`)

Add a fourth service-check type, `dns`, so STD can take over the DNS checks
that Gatus runs at the Emmett site today. It works like the existing http/tcp/ping service
checks end to end: model plus Alembic migration, the Add/Edit UI, the
management API and `openapi.json`, the MCP tools, history/badge/detail panel,
tests and docs. This is the first chunk of v0.9.0. Chunk 02 (cert expiry on
HTTPS checks) runs after it, so leave room for that but don't build it.

## What to do

1. **Dependency.** Add `dnspython` to `requirements.in` and regenerate
   `requirements.txt` with the command in that file's header
   (`uv pip compile --python-version 3.11 requirements.in -o requirements.txt`).
   Don't touch any other pins. If the compile tries to bump unrelated packages,
   pin them back or use `--upgrade-package dnspython` only.

2. **Model and migration.** Add `CHECK_TYPE_DNS = 'dns'` to `CHECK_TYPES`
   (`check_type` is String(8), which fits). Add nullable columns to
   `health_check`:
   - `dns_name` String(255): the query name.
   - `dns_record_type` String(8): A, AAAA, CNAME, TXT, PTR, MX, NS, SRV.
     Export a `DNS_RECORD_TYPES` tuple.
   - `dns_expected_rcode` String(16): default `NOERROR` when blank.
   - `dns_expected_answer` String(255): empty or NULL means "rcode only".

   `target` holds the **server**: `ip`, `ip:port`, `[v6]` or `[v6]:port`, with
   port 53 by default. The server must be an IP literal, not a hostname,
   because the check must never use the system resolver.

   Write one Alembic migration (`down_revision` = current head `d4a9e2c6b715`;
   verify with `alembic heads`). The new columns are not FKs, so they need no
   indexes. Include the new fields in `to_config()` and in restore.

3. **Probe** `checker.probe_dns(server, name, record_type, expected_rcode,
   expected_answer, timeout)`. Use dnspython at a low level:
   `dns.message.make_query` plus `dns.query.udp_with_fallback(q, ip,
   timeout=..., port=...)`, so it falls back to TCP on truncation. **Never** use
   `dns.resolver.Resolver()` with the system config.
   - For PTR, accept an IP as the name and convert it with
     `dns.reversename.from_address`. A name already in `in-addr.arpa` /
     `ip6.arpa` is used as is.
   - Get the rcode text from `dns.rcode.to_text`. If it doesn't match the
     expected rcode, the message is `rcode NXDOMAIN` (the actual rcode).
   - Answers are the rdatas in the answer section for the queried type, at
     any owner name, so a CNAME chain followed by an A record still matches
     the A record. Normalize before comparing: case-insensitive, trailing dot
     stripped on names, TXT as its joined strings without quotes. For MX and
     SRV, compare the full `to_text()` form, normalized the same way. The
     expected answer is an **exact match on any** answer record.
   - **NODATA:** NOERROR with no answers passes when no expected answer is
     set. When an expected answer is set, it fails with
     `no answer, expected 10.100.17.10`.
   - Wrong answer: `answer 10.0.0.5, expected 10.100.17.10`. With several
     answers, join them with ` | ` (`answer 10.0.0.5 | 10.0.0.6, expected
     ...`). Clip to the message column the way the other probes do.
   - A timeout (`dns.exception.Timeout`) gives exactly `timeout`. Other
     exceptions use the existing `_failure` path.
   - Latency is the query round trip. `status_code` stays None.
   - Hook it into `run_probe` (`check_type == "dns"`) and carry the DNS
     fields in the job dict built in `jobs.py`.

4. **Validation** (`check_form.py`; the form and the API share one rule set):
   - `validate_target("dns", target)` accepts an IP literal with an optional
     port 1–65535 (IPv6 in brackets when it has a port) and rejects hostnames
     with a clear message.
   - `validate_service_check` for dns:
     - `dns_name` is required and must be a valid DNS name, or an IP when the
       record type is PTR.
     - `dns_record_type` must be in `DNS_RECORD_TYPES`; default A.
     - `dns_expected_rcode` must be a known rcode text (`dns.rcode.from_text`
       succeeds); default NOERROR; stored upper-case.
     - `dns_expected_answer` is optional and trimmed.
     - `mode` and `verify` don't apply to dns. Store them as `status` and
       True, the same way tcp/ping do in `_assign`.
   - Update the type error message ("HTTP/HTTPS, TCP, Ping or DNS").
   - Add the DNS fields to `_signature` so editing them resets cached state
     the same way a target change does.
   - Form field names: `svc_<key>_dns_name`, `svc_<key>_dns_type`,
     `svc_<key>_dns_rcode`, `svc_<key>_dns_answer`. Update the module
     docstring.
