# Task: Purge MQTT topics and Home Assistant devices (channel-wide and per entry)

Give the operator a clean-slate tool.
- **Channel-wide:** remove every retained STD message and every STD
  discovery config from a channel's broker.
- **Per entry:** purge one entry's topics and HA device and republish it, so
  HA recreates the device with fresh entity ids (e.g. after a rename).

## What to do

1. **Channel purge.**
   - Run it on the publisher thread, or a worker it owns; never in the
     request thread beyond queuing.
   - For the given channel's live session, subscribe briefly (a few seconds,
     until the retained burst stops) to:
     - `<base>/#`;
     - `<ha_prefix>/+/std_<inst8>/#`, i.e. only this instance's node id.
       Check the exact node-id form in `notify_ha.py`.
   - Collect every topic that arrives with the retained flag, plus every
     topic in the persisted published set for that channel.
   - Publish an empty retained payload to each one, **except
     `<base>/status`** (the LWT). Leave that alone while connected.
   - Clear the channel's published-set bookkeeping (state and HA) so the
     reconcile doesn't think anything is still out there.
   - Option `republish: bool`. True runs a forced `full_sync()` afterwards,
     but only once HA has had time to process the removals; wait about 2 s
     and record the choice. False leaves the broker empty until the next
     change, connect or safety-net sync. In that case **suppress the
     automatic republish** until something changes. Pick and document a
     clean way, for example a `purged_until_change` flag, or simply have
     "False" also untick `ha_discovery`. Prefer the simplest behavior that
     an operator would find unsurprising, and record the decision.
   - Return counts (topics cleared, state vs discovery) for the UI.
2. **Entry purge-and-republish.**
   - Clear that entry's state topic, its check topics, and its HA discovery
     configs (device and all entities), on every channel.
   - Drop them from the published sets, wait about 2 s, then republish that
     entry, if it is still desired.
   - If the entry is not opted in to HA, purge only (state topics are
     republished as normal).
3. **UI.**
   - **Settings → Notifications, per channel:** a **"Purge MQTT and Home
     Assistant"** button with a confirm dialog that explains what it does.
     The dialog offers "republish afterwards" (default on). The result
     (counts) shows inline.
   - **Entry edit page:** a **"Purge and republish to MQTT/HA"** button,
     with a confirm, shown when any channel is enabled.
   - Use POST with CSRF, admin only.
4. **Management API / MCP.**
   - `POST /api/v1/notifications/channels/<id>/purge` with
     `{republish: bool}`, and `POST /api/v1/entries/<id>/notifications/purge`.
     Use admin scope, add them to `mgmt_openapi.py`, and match the error
     style.
   - MCP tools for both, requiring a write/admin key, following existing
     conventions.
5. **Tests**, with the fake paho client (extend `FakeClient` so subscribing
   delivers preset retained messages):
   - the purge clears both discovered and tracked topics;
   - it skips `<base>/status`;
   - it ignores another instance's HA node id;
   - the published set is empty afterwards;
   - republish true republishes, and false doesn't republish;
   - entry purge clears and republishes only that entry, on every channel;
   - an entry that isn't opted in only has its state purged;
   - API and MCP;
   - admin only.

   `uvx ruff@0.15.17 check .` and `/tmp/claude-1000/venv/bin/pytest -q`
   must pass.
