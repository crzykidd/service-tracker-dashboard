## What to do

1. **Testability seam.** Add a `STD_CONFIG_DIR` env var (default `/config`). Derive every hardcoded `/config/...` path from it: `app.py` (`DATABASE_PATH`, `LOGFILE`, `IMAGE_DIR`), `settings_loader.py` (`CONFIG_PATH`, `EXAMPLE_DEST`), and any others you find (`grep -rn "/config" --include='*.py' .`). Leave `alembic.ini` and the `Migration check` CI job alone. Production behavior must be byte-identical when the var is unset.
2. `app.py` builds `app = create_app()` at import. Keep that working for `python app.py`, alembic and scripts, but make sure tests can set `STD_CONFIG_DIR` (and other env) **before** the import. A session-scoped fixture that sets env, then imports, is acceptable. Don't restructure the factory beyond what's needed.
3. `requirements-dev.txt` with `-r requirements.txt` plus `pytest` (pinned). Not installed in the Docker image.
4. `tests/conftest.py`: a temp config dir, an app with `db.create_all()`, a test client, a helper that posts an authed register payload, and an admin-logged-in client fixture for later prompts.
5. Tests, written against **current** v0.6.8 behavior:
   - Register auth: correct bearer → 2xx; wrong/missing → 401.
   - Unknown top-level key and unknown nested key → 400 (`extra="forbid"`).
   - `exposure_observations` absent preserves existing `service_exposure` rows; `[]` clears them.
   - URL provenance: `ui_edit` is never overwritten by a register or by synthesis, `explicit_label` beats `synthesized`, and clearing a URL resets its source.
   - `register_field_ownership` `user_wins` vs `notifier_wins` on `group_name`/`sort_priority` (set via `app.config` directly, because the loader bug drops it).
   - Settings loader: ENV > file > default.
   - **Known bugs, as `xfail(strict=True)` with a reason pointing to PRD §12.3:** (a) `widget_value_retention_days` / `register_field_ownership` set in `settings.yml` reach `app.config`; (b) with no `api_token` configured, `Authorization: Bearer None` is rejected. Prompt v069-03 removes the xfail marks.
6. CI: add a `test` job named **`Test`** to `ci.yml` (Python 3.11, `pip install -r requirements-dev.txt`, `pytest -q`). It runs on push, like the others.
7. `standards.md`: remove the "Tests exempt" note from the code-checkin row and say the suite lives in `tests/`. CLAUDE.md "CI, Registry, and Releases": add `Test` to the required-check list and drop the exemption sentence. README Development: replace "no automated test suite yet" with how to run the tests. PRD §13: same update to the required-checks text.
8. In your report, tell the orchestrator that **the operator must add `Test` as a required check in GitHub branch protection** (manual step, not done by you).
