# Task: Add CSRF protection to all UI POSTs (PRD §12.4)

No POST form or JS fetch in STD is CSRF-protected. Add Flask-WTF `CSRFProtect`, thread the token through every form and fetch call, and exempt the bearer-token register API.

## Before you start

- Read `CLAUDE.md` (project rules + the three standards snippets — they apply).
- Read `docs/PRD.md` §12 intro and this task's subsection (named below);
  read the 2026-11-15 "v0.6.9 scope" entry in `docs/decisions.md`. The design
  calls there are settled — don't re-litigate them; if the code makes one
  impossible, stop and report rather than improvising.
- Part of the v0.6.9 sequence (`prompts/2026-11-15-v069-*.md`, run in number
  order). Confirm earlier prompts in the sequence are in `prompts/done/`; if one
  isn't, stop and report.
- PRD subsection: **§12.4**.
- Inventory first: `grep -rn "method=[\"']post" -i templates/`, and every `fetch(` with `method: 'POST'` in `static/js/` and inline template scripts. Also check every `methods=[...'POST'...]` route in `routes_*.py`.

## What to do

1. Add `Flask-WTF` to `requirements.txt` (pinned if v069-09 has already run; otherwise unpinned like the rest). Initialize `CSRFProtect` in `extensions.py`/`app.py`. Set `WTF_CSRF_TIME_LIMIT = None`.
2. Exempt the `/api/v1/register` view (`csrf.exempt`). Leave everything else protected, including `/login`, `/logout`, user management, settings, backup/restore uploads, group CRUD, add/edit/delete, and the `/api/v1/entries/<id>/delete` JSON endpoint (session-authenticated, so it needs CSRF).
3. Add `<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">` to every POST form. Add `<meta name="csrf-token" content="{{ csrf_token() }}">` to `base.html` and to `login.html` if it doesn't extend base. Add one shared JS helper (in an existing shared static JS file) that adds `X-CSRFToken` to POST fetches, and use it at every call site.
4. Handle `CSRFError`: for JSON or `fetch` requests (check `request.is_json`, `Accept`, or the `/api/` prefix), return `400 {"error": "CSRF token missing or invalid"}`; otherwise flash "Your session expired or the form was stale; please retry." and redirect to the referrer or the dashboard.
5. Tests: a POST without a token is rejected (form and JSON variants); a POST with a token succeeds; register stays exempt. The test config may disable CSRF globally for other tests (`WTF_CSRF_ENABLED=False`), but these CSRF tests must run with it enabled.
6. Manually smoke-test every POST flow if you can run the app locally (`STD_CONFIG_DIR` + `python app.py`), and list which ones you verified and which you didn't.
